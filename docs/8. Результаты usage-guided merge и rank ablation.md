# Результаты usage-guided merge и rank ablation

## Краткий вывод

Эксперимент завершен полностью: рассчитаны 30 validation-кандидатов и все 12
выбранных test-кандидатов, failed-записей нет. Абляция дала два отрицательных,
но полезных результата.

Во-первых, `usage_guided_merge` не превзошел `usage_prune`. Значит, хорошего
выбора малоиспользуемых экспертов недостаточно: сама операция усреднения весов
вносит дополнительную ошибку. Во-вторых, выбор спектрального ранга по одному
validation split не переносится на test. Более высокие ранги выигрывали на
validation, но в пяти из шести RMT-точек не улучшили test-результат относительно
прежнего rank 1.

Текущий stage gate на multi-layer RMT merge не пройден. Следующая итерация
должна сначала сделать выбор rank и весов устойчивым на нескольких validation
срезах. `usage_prune` остается контрольным верхним ориентиром качества.

## Диагностика usage-guided merge

Метод корректно выбирает малоиспользуемые source experts и сопоставляет их с
уникальными экспертами из сохраняемой части:

| Сжатие | Mean source usage | Mean partner usage | Mean functional similarity |
|---:|---:|---:|---:|
| 10% | 0.0115 | 0.0150 | 0.519 |
| 25% | 0.0135 | 0.0174 | 0.511 |
| 40% | 0.0146 | 0.0181 | 0.508 |

При этом ухудшение относительно `usage_prune` растет с 1.21 п.п. при 10% до
5.56 п.п. при 40%. Следовательно, основная потеря возникает после выбора
source experts: статическое усреднение весов пары не сохраняет функцию
удаляемого и принимающего экспертов. Для следующей merge-итерации нужны либо
usage-weighted coefficients, либо короткая компенсационная донастройка, либо
маршрутизатор, учитывающий изменившуюся геометрию экспертов.

## Ограничение throughput

Baseline PPL воспроизвелся точно, но baseline throughput изменился с 209.96 до
165.05 токенов/с без изменения модели и данных. Поэтому записанный в новом
summary прирост throughput на 25-30% отражает шум короткого одиночного прогона,
а не доказанное ускорение. Для вывода об инференсе нужны warmup, несколько
повторов, медиана и отдельная загрузка materialized checkpoint без rollback
snapshot. Параметрическая экономия в one-layer pilot также мала: 0.36-1.45%
от всей модели.

## Решение по stage gate

Переход текущего RMT pairing сразу на несколько слоев отклоняется. Причины:

1. ни один RMT-содержащий метод не превосходит `usage_prune`;
2. чистый RMT хуже простых merge-baselines на большинстве точек;
3. rank, выбранный на одном validation split, не переносится на test;
4. выигрыш по памяти одного слоя слишком мал для надежной оценки ускорения.

Следующая минимальная итерация:

1. разделить текущую validation-часть на несколько фиксированных срезов и
   выбирать rank по агрегированной деградации и ее дисперсии;
2. оставить test split недоступным до заморозки rank и весов;
3. после устойчивого выбора rank провести отдельную абляцию именованных
   `hybrid_pairing.variants`, не создавая полный cross-product сразу;
4. добавить usage-weighted merge как отдельный transform и сравнить его с
   `usage_prune` и текущим равновесным merge;
5. разрешить representative-layer pilot только если RMT-содержащий метод
   устойчиво не хуже `functional_cosine` и random baseline на всех долях.
