# Цель эксперимента

Эксперимент заключается в применение разработанного метода сжатия экспертов (смотри реализацию в разделе common) для модели "Qwen/Qwen1.5-MoE-A2.7B-Chat".

Эксперимент подразумевает создание новых сжатых слоев с нуля на основе заданной модели и наборов данных, интеграция их в архитектуру исходной модели, а также оценка изменений в скорости работы, объеме памяти вычислительного устройства, используемого при работе модели и точность модели на тестовом наборе. Большинство результатов сохранено в виде графиков, результаты точности моделей сохранены в виде списка значений.

# Структура проекта

Эксперимент реализован при помощи набора скриптов на языке python с применением pytorch и других библиотек.

Файлы имеют названия "N_*.py", где N - порядковый номер скрипта и соответствует тому, в каком порядке ожидается их запуск.

Скрипты `N_*.py` правятся напрямую и являются источником правды. Старые ноутбуки `N_*.ipynb` (если остались рядом) — legacy и из скриптов не регенерируются.

# Описание стадий эксперимента
Каждому шагу соответствует один скрипт (смотри скрипт с соответствующим номером).

Используются три выборки: train (подгонка сжатия и выбор порядка замены слоёв), validation (отложенная выборка для реконструкции, стадии 1-8) и test (только финальный замер точности на стадии 9). Раньше второй выборкой была test — теперь её роль выполняет validation.

## 1. Создание матрицы совместных активаций

Создает данные в разделе data/activations/S_N - квадратные матрицы с размерностью равной числу экспертов, где хранится число совместных активаций на тренировочных и валидационных данных.

## 2. Разбиение экспертов на пары

На основе матрицы совместных активаций, используя жадный алгоритм, строится оптимальное разбиение экспертов на пары.

## 3. Сохранение экспертов

Для каждого заданного mlp слоя отдельно сохраняются его внутренние блоки, включая каждого эксперта. Это позволяет в будущем удобнее с ними работать.

## 4. Сохранение входных значений

Тренировочные и валидационные данные проходят через модели и их значения на входах в интересующие нас mlp слои сохраняются в виде двухмерного тензора.

## 5. Сохранение данных для каждой пары

Для каждой пары выделяются входные данные, которые с ней активируются. Это позволяет в дальнейшем обучать сжатие только на релевантных данных.

## 6. Сжатие экспертов

Непосредственное применение алгоритма сжатия экспертов для выбранных пар на основе выделенных входных значений.

## 7. Итоговая статистика

Оценивает слои в отдельности на тренировочных и валидационных данных на основе относительных метрик.

## 8. Пример генерации

Приводит несколько примеров генерации до и после сжатия. Позволяет оценить различия итоговой модели с точки зрения изменения поведения.

## 9. Тест на реальных задачах

Модель тестируется в решении реальных задач без размышления и оценивается её точность ответов. Порядок последовательной замены слоёв выбирается на train (есть разметка), а финальная точность замеряется на test.

# Формат сохранения данных

Данные экспериментов сохраняются в разделах "data" и "plots"

В разделе "plots" сохраняются графики, полученные в ходе эксперимента в формате "plots/TYPE/*.png", где TYPE - тип эксперимента.

В разделе "data" сохраняются сырые данные для модели, в частности:
- data/activations/train_matrix_N - квадратные матрицы с размерностью равной числу экспертов, где хранится число совместных активаций на тренировочных данных
- data/activations/validation_matrix_N - квадратные матрицы с размерностью равной числу экспертов, где хранится число совместных активаций на валидационных данных
- data/pairs/N - оптимальное разбиение экспертов на пары в виде списка пар, полученное на основе тренировочных данных
- data/experts/N/* - составные части mlp слоя номер N, включая всех экспертов: expert_K, gate, shared_expert, shared_expert_gate
- data/mlp_inputs/train_N - входные данные на MLP блок слоя N, список тензоров
- data/mlp_inputs/validation_N - входные данные на MLP блок слоя N, список тензоров
- data/activations/train_all_N - список тензоров размера top_k, означающие активировавшихся экспертов на соотвествующем примере
- data/activations/validation_all_N - список тензоров размера top_k, означающие активировавшихся экспертов на соотвествующем примере
- data/activations/pairs_train_N входные данные на MLP блок слоя N для каждой пары экспертов, список индексов
- data/activations/pairs_validation_N входные данные на MLP блок слоя N для каждой пары экспертов, список индексов
- data/fusion_experts/N/i - сжатые эксперты из пары i на слою N
