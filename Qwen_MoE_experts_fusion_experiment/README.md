# Цель эксперимента

Эксперимент применяет метод сжатия экспертов из `common/` к модели
`Qwen/Qwen1.5-MoE-A2.7B-Chat`.

Пайплайн создает сжатые слои на основе заданной модели и наборов данных,
интегрирует их в исходную архитектуру и оценивает изменения скорости,
потребления памяти и точности на тестовом наборе. Результаты сохраняются в виде
графиков и списков значений метрик.

# Структура проекта

Эксперимент реализован набором Python-скриптов на PyTorch и связанных
библиотеках.

Файлы называются `N_*.py`, где `N` - порядковый номер стадии и ожидаемый порядок
запуска. Каждая стадия остается в отдельном файле, чтобы результаты и побочные
артефакты разных шагов не смешивались.

# Описание стадий эксперимента

Каждому шагу соответствует один скрипт с тем же номером.

## 1. Создание матрицы совместных активаций

Создает данные в `data/activations/S_N`: квадратные матрицы размером по числу
экспертов, где хранится число совместных активаций на тренировочных и тестовых
данных.

## 2. Разбиение экспертов на пары

На основе матрицы совместных активаций, используя жадный алгоритм, строится оптимальное разбиение экспертов на пары.

## 3. Сохранение экспертов

Для каждого заданного mlp слоя отдельно сохраняются его внутренние блоки, включая каждого эксперта. Это позволяет в будущем удобнее с ними работать.

## 4. Сохранение входных значений

Тренировочные и тестовые данные проходят через модель, а значения на входах в
интересующие MLP-слои сохраняются в виде двумерного тензора.

## 5. Сохранение данных для каждой пары

Для каждой пары выделяются входные данные, которые с ней активируются. Это позволяет в дальнейшем обучать сжатие только на релевантных данных.

## 6. Сжатие экспертов

Непосредственное применение алгоритма сжатия экспертов для выбранных пар на основе выделенных входных значений.

## 7. Итоговая статистика

Оценивает слои в отдельности на тренировочных и тестовых данных на основе относительных метрик.

## 8. Пример генерации

Приводит несколько примеров генерации до и после сжатия. Позволяет оценить различия итоговой модели с точки зрения изменения поведения.

## 9. Тест на реальных задачах

Модель тестируется на реальных задачах без рассуждений, после чего оценивается
точность ответов.

# Формат сохранения данных

Данные эксперимента сохраняются в разделах `data` и `plots`.

В `plots` сохраняются графики в формате `plots/TYPE/*.png`, где `TYPE` - тип
эксперимента.

В `data` сохраняются сырые данные для модели:

- `data/activations/train_matrix_N` - матрицы совместных активаций на
  тренировочных данных.
- `data/activations/test_matrix_N` - матрицы совместных активаций на тестовых
  данных.
- `data/pairs/N` - разбиение экспертов на пары, полученное на тренировочных
  данных.
- `data/experts/N/*` - составные части MLP-слоя `N`, включая `expert_K`, `gate`,
  `shared_expert` и `shared_expert_gate`.
- `data/mlp_inputs/train_N` - входные данные MLP-блока слоя `N` на тренировочной
  выборке.
- `data/mlp_inputs/test_N` - входные данные MLP-блока слоя `N` на тестовой
  выборке.
- `data/activations/train_all_N` - активировавшиеся эксперты размера `top_k` на
  тренировочных примерах.
- `data/activations/test_all_N` - активировавшиеся эксперты размера `top_k` на
  тестовых примерах.
- `data/activations/pairs_train_N` - индексы входных данных для каждой пары
  экспертов на тренировочной выборке.
- `data/activations/pairs_test_N` - индексы входных данных для каждой пары
  экспертов на тестовой выборке.
- `data/fusion_experts/N/i` - сжатый эксперт из пары `i` на слое `N`.
