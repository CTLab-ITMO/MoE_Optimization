# Цель эксперимента

Эксперимент заключается в применение разработанного метода сжатия экспертов (смотри реализацию в разделе common) для модели "Qwen/Qwen1.5-MoE-A2.7B-Chat".

Эксперимент подразумевает создание новых сжатых слоев с нуля на основе заданной модели и наборов данных, интеграция их в архитектуру исходной модели, а также оценка изменений в скорости работы, объеме памяти вычислительного устройства, используемого при работе модели и точность модели на тестовом наборе. Большинство результатов сохранено в виде графиков, результаты точности моделей сохранены в виде списка значений.

# Структура проекта

Эксперимент реализован набором скриптов на python (pytorch и др.) и запускается **только из корня репозитория** пакетными импортами (`from experts_fusion.config import ...`, `from common... import ...`), без `sys.path.append`. Полный прогон — `python -m experts_fusion.run` (можно подмножество стадий: `python -m experts_fusion.run 1 2`).

Файлы имеют названия `N_*.py`, где N — порядковый номер стадии. Скрипты — единственный источник правды.

# Описание стадий эксперимента

Пайплайн собран в **четыре стадии**. Стадии общаются только через сохранённые артефакты-классы и общую раскладку путей (`common/layout.py`). Используются три выборки: train (подгонка сжатия и выбор порядка замены слоёв), validation (отложенная выборка для реконструкции) и test (только финальный замер точности).

## 1. Предобработка и захват сырых данных (`1_preprocess.py`)

Два под-шага. **1a** — извлечение весов (на CPU, без датасета): для каждого MoE-слоя сохраняются эксперты (через `EXPERT_ADAPTER`), gate и shared-эксперт. **1b** — захват за один проход недеструктивными forward-hooks: одновременно собираются матрица совместных активаций (`CoActivationMatrix`), входы MLP-блоков и сырые top-k селекции. Сигнал группировки (со-активации) не зависит от самой группировки, поэтому живёт здесь. Стадия пишет провенанс: `config_snapshot.json`, `run_manifest.json`, `_layout_version`.

## 2. Группировка и индексация активаций (`2_grouping.py`)

Чистый CPU-шаг без модели. Зарегистрированная стратегия группировки разбивает экспертов слоя на `Partition` (сохраняется под `groups/`, заменяет legacy `pairs/`). Затем top-k селекции join-ятся с разбиением в `GroupActivationIndex` — для каждой группы индексы примеров, которые её активируют. Смена метода группировки не требует повторного прогона модели.

## 3. Применение метода слияния (`3_fusion.py`)

Для каждой группы каждого слоя эксперты сливаются каждым зарегистрированным методом, выбор по метрикам даёт псевдо-методы `Best_<metric>` (фолбэк — первый зарегистрированный метод, не хардкод). Результаты — версионированные `FusedExpert`. Идемпотентность/докаты: каждый артефакт несёт хеш апстрим-входов в провенансе, повторный прогон пропускает свежие единицы работы.

## 4. Тестирование сжатия (`4_evaluate.py`)

Базовая модель грузится **один раз** (load-once); для каждого метода MoE-слои подменяются на собранный из артефактов слой и гарантированно восстанавливаются между методами. Замеряется итоговая точность (порядок замены — на train, финал — на test), плюс best-effort диагностика: реконструкционные метрики и качественная генерация. Все выходы scoped под `DATA_DIR` (`test_result_*`).

# Формат сохранения данных

Все артефакты scoped под `DATA_DIR`. Версионированные артефакты (`CoActivationMatrix`, `Partition`, `GroupActivationIndex`, `FusedExpert`) сериализуются как `state_dict` + JSON-заголовок поверх `safetensors` (никогда не пиклятся `nn.Module`); провенанс-слот несёт seed/commit/config-hash/хеш апстрим-входов.

- `data/_layout_version` — версия раскладки `DATA_DIR`
- `data/config_snapshot.json` — канонический снимок конфига (стадии 2-4 сверяются с ним)
- `data/run_manifest.json` — провенанс прогона
- `data/activations/{train,validation}_matrix_N` — `CoActivationMatrix` (EXPERTS×EXPERTS со-активации)
- `data/groups/N` — `Partition` слоя N (разбиение на группы, заменяет `pairs/`)
- `data/groups/{train,validation}_activations_N` — `GroupActivationIndex` (индексы примеров на группу)
- `data/experts/N/*` — части MLP-слоя N: `expert_K`, `gate`, `shared_expert`, `shared_expert_gate`
- `data/mlp_inputs/{train,validation}_N` — входы MLP-блока слоя N, список тензоров
- `data/activations/{train,validation}_all_N` — сырые top-k селекции на пример
- `data/fusion_experts/<method>/N/i` — `FusedExpert` группы i слоя N методом `<method>`
- `data/test_result_*/accuracy/*` — списки точности по методам и режимам замены
