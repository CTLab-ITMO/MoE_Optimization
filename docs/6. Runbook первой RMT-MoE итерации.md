# Runbook первой RMT-MoE итерации

## Назначение

Первая итерация проверяет one-layer гипотезу H1 на реальных activation traces:

`dataset -> traces -> functional sketches -> finite-size RMT diagnostics -> candidate plans -> reversible merge/prune -> validation selection -> test evaluation`.

Она не проверяет multi-layer compression, dynamic-k, router bias или distributed communication.

## Что считается experiment-ready

Запуск является научным, а не только техническим, если одновременно выполняются условия:

1. `calibration.source` равен `hf_dataset` или указывает на заранее собранный реальный artifact.
2. Calibration, validation и test являются непересекающимися наборами.
3. RMT diagnostics содержат `r_detect`, `r_stable`, `r_useful`, empirical null edge и principal-angle stability.
4. Candidate model реально применяется к одному MoE-слою и восстанавливается после оценки.
5. Baseline и candidates используют одни и те же token batches и profiler settings.
6. Test используется только для кандидатов, выбранных по validation.
7. Каждый завершённый candidate сохраняется в JSONL до запуска следующего.

## Окружение

Не переустанавливать рабочую CUDA-сборку Torch. Установить только experiment dependencies:

```bash
python -m pip install -r requirements-experiment.txt
```

Проверить runtime:

```bash
python -m moe_opt_runner.preflight \
  --config configs/experiments/h1_rmt_one_layer_pilot.json \
  --require-cuda \
  --check-model-config
```

Запускать эксперимент можно только при `"ready": true`.

## Запуск

```bash
python -m pytest -q
python -m moe_opt_runner.main \
  --config configs/experiments/h1_rmt_one_layer_pilot.json
```

## Первая сетка

- модель: `Qwen/Qwen1.5-MoE-A2.7B-Chat`;
- слой: `0` как инженерный smoke; после него выбрать один ранний, средний и поздний слой;
- методы: `random_merge`, `usage_prune`, `functional_cosine`, `rmt_geometry`;
- compression fractions: `0.10`, `0.25`, `0.40`;
- quality budgets: `0.01`, `0.03`, `0.05` relative perplexity degradation;
- три seed для random baseline;
- RMT и deterministic baselines запускаются один раз на configuration point.

## Артефакты

В `artifacts/h1_rmt_one_layer_pilot` формируются:

- `traces/trace_manifest.json`;
- `h1_diag_0.json` и `h1_diag_0.pt`;
- `pairs_0.pt`;
- `pilot_runs.jsonl` с baseline, completed и failed candidates;
- `pilot_summary.json`;
- `artifacts_manifest.json` и `run_summary.json`.

`pilot_runs.jsonl` является первичным журналом. `pilot_summary.json` является производным отчётом.

## Интерпретация первой итерации

Главная диаграмма строится по трём осям:

- relative perplexity degradation;
- active model parameter memory reduction;
- measured tokens per second.

`peak_memory_mb` внутри reversible session является диагностикой процесса, но не доказательством memory reduction: исходные параметры удерживаются rollback snapshot. Физическое снижение peak memory подтверждается позднее загрузкой отдельного materialized checkpoint.

RMT-кандидат считается перспективным, если:

1. проходит хотя бы quality budget `3%` на validation и test;
2. не хуже random/functional-cosine при одинаковой compression fraction;
3. имеет воспроизводимые `r_stable/r_useful` и principal angles;
4. даёт положительное снижение active parameter memory;
5. не демонстрирует систематического падения throughput.

## Следующий gate

После успешной one-layer итерации запускаются три representative layers. Только после подтверждения воспроизводимости добавляются:

1. materialized checkpoint reload для честного peak-memory профиля;
2. multi-layer controller `keep/prune/merge/abstain`;
3. H2 router bias;
4. H3 dynamic-k;
5. communication-aware profiling.
