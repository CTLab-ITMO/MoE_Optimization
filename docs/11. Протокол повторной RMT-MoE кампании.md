# Протокол повторной RMT-MoE кампании

## Назначение

Кампания закрывает пять задач перед отдельным обсуждением ускорения:

1. сравнение методов на нескольких seed и повторные измерения скорости;
2. абляция спектрального ранга;
3. послойный гибридный выбор метода;
4. проверка улучшенных весов объединения экспертов;
5. последовательное масштабирование на `3`, `6`, `12` и `24` слоя.

Изменение `top-k`, собственные CUDA-ядра и объединённые операции GPU в эту
кампанию не входят.

## Два последовательных запуска

### Репрезентативная кампания

Конфигурация:
`configs/experiments/h1_rmt_rank_merge_representative_campaign.json`.

Слои: `0`, `11`, `23`. Для каждого из seed `2026`, `2027`, `2028` верхняя
оценка размера сетки составляет 186 однослойных кандидатов. Число включает
фиксированные и диагностические ранги, поэтому фактическая сетка может быть
меньше после удаления совпадающих рангов.

Проверяются:

- `usage_prune`, `functional_cosine`, `rmt_functional_usage`;
- доли `0.10` и `0.25`;
- ранги `1`, `2`, `4`, `8`, `16`, полезный RMT-ранг, MP-ранг и ранги для
  объяснённой дисперсии `0.90` и `0.95`;
- `uniform`, `usage_bounded` и `functional_ridge` для объединения;
- режимы `static` и `adaptive`;
- послойный `hybrid`-рецепт.

### Полная модель

Конфигурация: `configs/experiments/h1_rmt_multilayer_full_model.json`.

Чувствительность измеряется на слоях `0`, `5`, `11`, `17`, `23`. Проверка
многослойных рецептов выполняется последовательно для `3`, `6`, `12` и `24`
слоёв. Следующий масштаб открывается только тогда, когда предыдущий содержит
хотя бы один рецепт с устойчивой деградацией не выше 5%.

## Правило отбора

Проверочный отбор сохраняет отдельную ячейку для каждой комбинации:

`семейство метода x доля сжатия x число слоёв`.

Между `static` и `adaptive` внутри ячейки выбирается лучший режим. Дополнительно
добавляются глобальные победители, поэтому различие режимов не исчезает из
анализа полностью. Такая схема не позволяет простому `usage_prune` вытеснить
RMT-кандидатов до тестовой выборки и одновременно ограничивает число дорогих
тестовых прогонов.

Для материализации сначала выбирается лучший рецепт максимального масштаба из
каждого семейства методов. Оставшиеся места заполняются следующими рецептами по
устойчивой проверочной оценке.

## Ограниченные команды

Один процесс обрабатывает ограниченное число элементов и после каждого
успешного элемента дописывает журнал `multilayer_runs.jsonl`.

```bash
export CONFIG=configs/experiments/h1_rmt_rank_merge_representative_campaign.json
export SEED=2026

.venv/bin/python -m moe_opt_runner.multilayer_cli \
  --config "$CONFIG" --replication-seed "$SEED" --step status

.venv/bin/python -m moe_opt_runner.multilayer_cli \
  --config "$CONFIG" --replication-seed "$SEED" \
  --step sensitivity_validation --max-items 8 --max-step-seconds 1200

.venv/bin/python -m moe_opt_runner.multilayer_cli \
  --config "$CONFIG" --replication-seed "$SEED" \
  --step multilayer_validation --max-items 1 --max-step-seconds 1200

.venv/bin/python -m moe_opt_runner.multilayer_cli \
  --config "$CONFIG" --replication-seed "$SEED" \
  --step test_selected --max-items 1 --max-step-seconds 1200
```

Остальные этапы запускаются по значению `next_step`. Одновременно допускается
только один записывающий процесс для одного seed.

## Межсидовая сводка

После трёх завершённых запусков:

```bash
.venv/bin/python -m moe_opt_runner.multilayer_campaign_cli \
  --config configs/experiments/h1_rmt_rank_merge_representative_campaign.json
```

Файл `campaign_summary.json` содержит:

- завершённые и отсутствующие seed;
- медиану, 5-й и 95-й процентили и худшую деградацию perplexity;
- медиану и диапазон изменения пропускной способности;
- снижение параметров и долю прохождения бюджета качества;
- частоты победивших рангов и политик весов по слоям.

Частичную сводку можно получить с `--allow-partial`, но её нельзя использовать
для окончательного выбора конфигурации.

## Критерий перехода к полной модели

Переход разрешается, если:

1. завершены все три seed без отсутствующих обязательных ячеек;
2. хотя бы один RMT-содержащий рецепт проходит бюджет 5% на всех трёх seed;
3. медианная деградация выбранного RMT-рецепта не выше 3%;
4. материализованный результат воспроизводит качество обратимого преобразования;
5. нет систематического ухудшения относительно `functional_cosine` на каждом
   репрезентативном слое;
6. результаты скорости основаны на пяти тестовых и десяти материализованных
   повторах, а не на одном коротком измерении.

## Остановка перед ускорением

После успешного этапа `24` слоя фиксируются качество, размер, память и скорость.
Далее кампания останавливается. Перенос параметрического сжатия на ускорение
инференса рассматривается отдельно: через физически компактную структуру,
переназначение маршрутизатора и специализированные операции GPU.
