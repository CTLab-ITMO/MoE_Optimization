
# Реализация первой гипотезы для одного слоя MoE
## unfolding в MoE-слое

Пусть в слое L есть E экспертов.

1. Делаем матрицу экспертов - $X \in \mathbb{R}^{E \times D},\quad X[e,:]=\mathrm{vec}(W_e)$
2. Если эксперт — это MLP из двух линейных, то  $\mathrm{vec}(W_e) = [\mathrm{vec}(W^{(1)}_e),\ \mathrm{vec}(W^{(2)}_e)]$
3. Биасы по желанию можно игнорировать или добавлять отдельно
4. Теперь “эксперты как точки” и спектр X показывает, сколько реально независимых “режимов” есть среди экспертов.

## Spike detection  - сколько “реальных” степеней свободы среди экспертов


1. Центрируем по экспертам - $X_c = X - \mathbf{1} \mu^\top,\quad \mu=\frac{1}{E}\sum_e X[e,:]$
2. Считаем несколько сингулярных значений $s_1\ge \dots \ge s_K$
3. Оцениваем уровень шума $\hat\sigma$ 
4. Порог - $\tau \approx \hat\sigma(\sqrt{D}+\sqrt{E}$)$
5. Спайки это те  $s_i$​, что существенно выше $\tau$. Их число $k_\star$ оценка “сколько направлений специализации реально видно”.
6. Можно использовать стабильный эвристический тест через "локоть" в спектре (elbow point) либо отношение $s_i/s_{i+1}$$ или $s_i/\text{median}(s)$

## Кластеризация экспертов в найденном сигнальном пространстве

1. Берём эмбеддинг экспертов - $Y = U_{:,1:k_\star} \Sigma_{1:k_\star} \in \mathbb{R}^{E\times k_\star}$
2. Кластеризуем строки $Y[e,:]$ (k-means / hierarchical).  
3. Число кластеров K минимально разумно $K=k_\star$​, максимум — E, на практике для одного слоя $K=\min(E,\max(1,k_\star))$ 

## Merge внутри кластера: два режима

### Быстрый baseline - weight averaging + rescaling

$W_{\text{meta}} = \sum_{e\in C} \alpha_e W_e,\quad \alpha_e \propto \text{usage}(e)$ правда может “размывать” разные субпространства.

### Через геометрию - mean-subspace + проекция + shrinkage

1. Для каждого $e\in C$ берём базис с рангом r например, по $W^{(1)}_e$​ или по конкатенации.
2. Считаем $U_\star$​ как mean подпространство projection mean.
3. Проецируем и усредняем - $\tilde W_e = U_\star U_\star^\top W_e \quad(\text{или двусторонне с }V_\star)$
4. $W_{\text{meta}} = \sum_{e\in C} \alpha_e \tilde W_e$
5. **Shrinkage** - делаем SVD $W_{\text{meta}}=U\Sigma V^\top$, заменяем $\Sigma$ на $\eta(\Sigma)$ 
6. Это даёт “средний эксперт” как **средний оператор в среднем подпространстве**
## “one-layer experiment”
- Выбираем слой L и заменяем его экспертов с E на K.
- Роутер этого слоя тоже меняем на размерность K.
- Остальные слои не трогаем

## Что считаем
- 1. Perplexity/CE loss на фиксированном вал-корпусе (например, 50–200k токенов).
- 2. Если есть lm-eval harness: 3–5 задач (MMLU subset, ARC-Easy/Challenge, GSM8K small, etc.) — на малом подмножестве для раннего отбора.
- Throughput - фиксируем batch size, seq len, dtype, kv-cache режим:
	- tokens/sec по 30–100 итерациям после warmup,
	- отдельно меряем роутер+dispatch overhead, эксперт-compute, общую латентность.

import torch

@torch.no_grad()
def build_X_from_layer(experts, mode="concat"):
    # experts: list of expert modules for one layer
    vecs = []
    for e in experts:
        # пример: MLP expert with W1, W2
        W1 = e.w1.weight.data
        W2 = e.w2.weight.data
        v = torch.cat([W1.reshape(-1), W2.reshape(-1)], dim=0)
        vecs.append(v)
    X = torch.stack(vecs, dim=0)  # [E, D]
    X = X - X.mean(dim=0, keepdim=True)
    return X

@torch.no_grad()
def spike_rank(X, K=16):
    E, D = X.shape
    # Для E<=64 часто можно exact SVD
    s = torch.linalg.svdvals(X)  # [min(E,D)]
    # грубая оценка шума: по хвосту спектра
    tail = s[min(len(s)-1, max(1, E//2)):]
    sigma = tail.median() / (torch.sqrt(torch.tensor(D, device=X.device)) + torch.sqrt(torch.tensor(E, device=X.device)) + 1e-8)
    tau = sigma * (torch.sqrt(torch.tensor(D, device=X.device)) + torch.sqrt(torch.tensor(E, device=X.device)))
    k = int((s > 1.2 * tau).sum().item())  # 1.2 — запас от ложных "спайков"
    k = max(1, min(k, E-1))
    return k, s, tau

@torch.no_grad()
def embed_experts(X, k):
    # X: [E, D]
    U, S, Vt = torch.linalg.svd(X, full_matrices=False)
    Y = U[:, :k] * S[:k]  # [E, k]
    return Y

@torch.no_grad()
def projector_mean(U_list, r):
    # U_list: list of [d, r] orthonormal bases
    P = 0.0
    for U in U_list:
        P = P + U @ U.T
    P = P / len(U_list)
    evals, evecs = torch.linalg.eigh(P)  # ascending
    U_star = evecs[:, -r:]               # top-r
    return U_star

@torch.no_grad()
def merge_cluster(expert_weights, usage_weights=None, r=64, do_shrink=True):
    # expert_weights: list of weight matrices W_e (same shape)
    # usage_weights: list of scalars alpha_e (sum to 1), else uniform
    n = len(expert_weights)
    if usage_weights is None:
        usage_weights = [1.0/n]*n

    # build subspace bases from each W_e via top-r left singular vectors
    U_list = []
    for W in expert_weights:
        U, S, Vt = torch.linalg.svd(W, full_matrices=False)
        U_list.append(U[:, :r])

    U_star = projector_mean(U_list, r)

    # project + average
    W_meta = 0.0
    for alpha, W in zip(usage_weights, expert_weights):
        Wp = U_star @ (U_star.T @ W)
        W_meta = W_meta + alpha * Wp

    if do_shrink:
        U, S, Vt = torch.linalg.svd(W_meta, full_matrices=False)
        # простая shrinkage: soft-threshold
        tau = S.median() * 0.5
        S2 = torch.clamp(S - tau, min=0.0)
        W_meta = (U * S2) @ Vt

    return W_meta


# Меняем z-нормализацию роутера через shrinkage

Делаем **денойзинг среднего вектора importance** через _covariance shrinkage_ низкоразмерный, быстрый вариант потому что число экспертов обычно небольшое (8–64).

## Данные

1. Для токена t считаем importance-вектор $c_t \in \mathbb{R}^E$ Собираем матрицу- $C \in \mathbb{R}^{N \times E}$ где N — число токенов/примеров.
2. Нам нужен $b \in \mathbb{R}^E$ который добавляется к логитам роутера.

## 3.2. Shrinkage-схема

1. Считаем среднее - $m = \frac{1}{N}\sum_t c_t$
2. Оцениваем ковариацию - $S = \frac{1}{N-1}(C - \mathbf{1}m^\top)^\top (C - \mathbf{1}m^\top) \in \mathbb{R}^{E\times E}$
3. Делаем shrinkage ковариации к “сферической”  - $\hat\Sigma = (1-\alpha)S + \alpha \mu I,\quad \mu=\frac{\mathrm{tr}(S)}{E}$​
4. Где α∈[0,1] можно либо взять фиксированно (например, 0.1–0.3), либо оценить по Ledoit–Wolf.
5. Деноизим mean через “ridge” - $b_\text{raw} = (\hat\Sigma + \lambda I)^{-1} m$
6. Компоненты mean, лежащие в направлениях высокой дисперсии (шумные направления), **подавляются**.
7. Масштабируем  $b = \epsilon \cdot \frac{b_\text{raw}}{\|b_\text{raw}\|_2 + \delta}$ и добавляем в роутер к логитам.
8. z-score работает покоординатно, игнорируя корреляции между экспертами. shrinkage ковариации + “ridge-whitening” уменьшает ложные предпочтения, возникающие из-за совместных флуктуаций экспертов
# Вторая гипотеза - routing budget по “структурности” (наличию спайков) роутинга

После 1 гипотезы у нас меньше экспертов значит роутер компактнее, спектральные индикаторы дешевле, динамика k не будет бороться с очевидной избыточностью.
Для окна токенов (например, один батч или скользящее окно длиной T) берём матрицу логитов от роутера (или gate-prob) $G \in \mathbb{R}^{T \times K}$ и считаем маленькую матрицу - $M = \frac{1}{T}G^\top G \in \mathbb{R}^{K\times K}$ и её с.з. $\lambda_1 \ge \dots \ge \lambda_K$

## Индикаторы “есть ли структура”

Два дешёвых индикатора:

1. **Spikiness ratio** - $\rho = \frac{\lambda_1}{\frac{1}{K}\sum_i \lambda_i + \varepsilon}$. Если $\rho \approx 1$ — распределение похоже на шу. Если $\rho \gg 1$ — есть сильный режим роутинга.

2. **Effective rank** - $r_\text{eff} = \exp\left(-\sum_i p_i \log p_i\right),\quad p_i=\frac{\lambda_i}{\sum_j \lambda_j}$. Если $r_\text{eff}$ мал — данные лежат в низкоразмерной структуре
## Правило выбора k 
- если $\rho < \rho_1$​ → k=1
- если $\rho_1 \le \rho < \rho_2$​ → k=2
- если $\rho \ge \rho_2$​ → k=4 или $k=\min(4,K)

Порог $\rho_1,\rho_2$​ калибруем на вал-сет - цель **вписаться в 5–10%** деградации качества.
## Cтабилизация load balance

Dynamic-k легко вызывает коллапс нагрузки. Нужно:
- ограничение на минимальную вероятность выбора эксперта
- либо стандартный лосс для load-balancing
- плюс “capacity factor” на максимальное количество токенов на эксперта.

## Как это склеить в один экспериментальный пайплайн

1. 1 гипотеза -  на слое L → уменьшили экспертов - $E\to K$. Измерили loss/качество + tokens/s.
    
2. гипотеза про нормализацию - на этом же слое L  добавили b (расшумленный) в роутер, измерили стабильность/качество.
    
3. Гипотеза про динамический роутинг - включили dynamic-k на слое L → добили throughput, проверили, что деградация всё ещё ≤5–10%.

## 1) Grassmann manifold → “средний эксперт”
### Почему это полезно именно для MoE-merge
Если эксперты реально избыточны, то их $U_e$ должны **кластеризоваться** на Grassmann и тогда merge можно формулировать как: _“заменить кластер экспертов одним представителем (Средний эксперт) + локальная донастройка (ZipIt/LSQ)”_.
### Какие есть проблемы

- “Эксперт → подпространство” зависит от **распределения входов**. Значит нужно фиксировать протокол выборки $x_i$ - какие слои, какие датасеты/сплиты.
    
- Frechet mean — **невыпуклый** минимум: возможны локальные решения. Надо фиксить через инициализацию (проекторное среднее) и малый r. Выбор r — гиперпараметр. он естественно связывается со “spike rank”.
### Что именно является “точкой” на многообразии

Для конкретного эксперта нам надо выбрать **подпространство признаков**, которое стабильно описывает его “геометрию”:

- **Параметрический вариант:**  
	- Берем веса $W_e$ и представляем эксперта подпространством, натянутым на топ-r сингулярных векторов
	- Либо столбцовое подпространство $\mathcal{U}_e = \mathrm{span}(U_{e,r}) \subset \mathbb{R}^{d_{\text{out}}}$​ либо строковое - $\mathcal{V}_e = \mathrm{span}(V_{e,r}) \subset \mathbb{R}^{d_{\text{in}}}$V
- **Функциональный вариант под реализацию в репо:**  
	- Берем набор входов в MoE-MLP, которые логируются в `mlp_inputs` и смотрим **выходы эксперта** $Y_e \in \mathbb{R}^{N \times d}$. Строим матрицу откликов эксперта $Y_e = [f_e(x_1), \dots, f_e(x_N)]^\top \in \mathbb{R}^{N \times d}$ ее также можно рандомизировано спроецировать
	- $U_e(:,1..k)$ или $V_e(:,1..k)$ - в зависимости от того, где удобнее жить в sample-space или feature-space
	- Тогда $\mathcal{U}_e = \mathrm{span}(\text{top-}r \text{SVD}(U_e / V_e))$
	- Это лучше коррелирует с качеством и не требует тяжелого разложения весов.

В обоих случаях точка("эксперт") на задаётся ортонормированным базисом, но **важно** помнить что базис не уникален, уникально подпространство - $U_e \in \mathbb{R}^{d \times r}$ c условием $Ue^{T}Ue=I$
### Как считать метрику и “среднее”
Fréchet mean — это аргмин среднего квадрата геодезических расстояний на многообразии - $U_\star = \arg\min_{U\in \mathrm{Gr}(r,d)} \sum_e w_e\, d^2(U, U_e)$ 
**Почему это полезно для merge:** если два эксперта функционально избыточны, их подпространства имеют малые principal angles ⇒ mean даёт “центральное” подпространство, на котором можно:
- определить _геометрически согласованный_ “средний” функционал,
- оценивать ожидаемый quality drop через углы/возмущения спектра (Davis–Kahan/Wedin).

Если подпространства “не слишком далеко” (малые углы), хорошая инженерная аппроксимация то Projection/chordal mean — почти всегда достаточно и существенно проще.
1. Подпространство - проектор $P_e = U_e U_e^\top$
2. Берем средний проектор $\bar P = \frac{1}{m}\sum_e P_e$
3. “Среднее подпространство” — топ-r собственных векторов $\bar P$.
4. “Средний эксперт” как _веса_ не уникален поэтому фиксируем архитектуру эксперта (gate/up/down),
5. Калибруем веса на кэше X под целевую функцию - $\min_{\theta} \sum_i \| f_\theta(x_i) - \tfrac{1}{2}(f_{e_1}(x_i)+f_{e_2}(x_i))\|^2$

Это даёт “среднего эксперта” в смысле минимизации chordal distance через проекторы. Можно считать итеративно и дорого:
- Инициализация $U^{(0)}$ (например, один из $U_e$​ или SVD от “среднего” проекторного матожидания).
- Итерации:
    - Для каждого $U_e$ считаем **log map** $\Delta_e = \log_{U^{(t)}}(U_e)$ (элемент касательного пространства).
    - Усредняем $\bar{\Delta} = \sum_e w_e \Delta_e$
    - Обновляем **exp map / retraction** -$U^{(t+1)} = \mathrm{Retr}_{U^{(t)}}(\eta \bar{\Delta})$
    - Стоп по норме $\bar{\Delta}$.

## Гипотеза 2 -  замена z-нормализации bias роутера на  через shrinkage

Ключевая идея в том что importance-вектор по экспертам — это **signal+noise**. Вместо z-score:

1. Центрируем importance,
    
2. Проецируем его на **spike-subspace** роутера (через спектр `gate.weight`),
    
3. "Виннеровское" усечение по компонентам,
    
4. Нормируем (max-abs).

В `WES_auto_bias_*` ключевая проблема это то что importance шумный и дорогой. В `compute_expert_importance()`  -  `top_k = layer.mlp.num_experts` или `layer.block_sparse_moe.num_experts` то есть **вычисляются все эксперты**, а не реальный `num_experts_per_tok`. Это увеличивает шум т.к. мы учитываем экспертов, которые никогда не исполняются при реальном inference), радикально увеличивает compute и делает bias "бесполезным на инфре" потому что он оптимизируется под другой режим роутинга. Минимальный фикс - -top-k брать из конфигурации (или аргумента), а не `num_experts`.

### Shrinkage под нашу схему

1. Covariance shrinkage + whitening по importance (но тогда надо собирать importance по семплам)

	- Собираем матрицу - $X_{\text{imp}}\in\mathbb{R}^{N\times E}$(по батчам/токенам),
	    
	- ковариация $S=X^\top X/N$
	    
	- Делаем shrinkage к $\mu I$ и берём whitened mean $v = S_{\text{shr}}^{-1}\bar x$
	    
	- Нормируем и делаем `gate.bias += eps * v`.
    

2. RMT-усечение через “спайки роутера” (работает даже если только один агрегированный вектор importance)

	- Берем матрицу роутера $W_{\text{gate}}\in\mathbb{R}^{E\times d}$
	- Cчитаем матрицу Грамма $S = W W^\top/d$
	- Расскладываем ее через любой вариант м.б. даже рандомизированный, bulk-edge порог (MP-эвристика),
	- Проецируем importance на spike-подпространство и усекаем компоненты.
	- Это фиксит шум у importance - мы запрещаем ему “гулять” в направлениях, которые роутер сам не различает устойчиво (они похожи на шум).

Реализация - `MoE_auto_bias_experiments/shrinkage_router_bias.py`  

В Qwen-MoE есть `shared_expert` + `shared_expert_gate`. Если  считаем importance по градиенту “на выходе слоя”, shared-ветка может забирать значимую долю градиента и искажать attribution на конкретные sparse-эксперты. Для чистоты эксперимента “bias на sparse-эксперты” стоит хотя бы в ablation:

- считать importance **без shared-ветки** (или вычитать shared_output из финального латетного состояния перед attribution),
- либо учитывать shared отдельно, не смешивая со sparse importance.

## Гипотеза 3 -  динамичекий роутинг после снятия избыточности экспертов

Динамический k должен быть **локальным по токену* , **дешёвым** (иначе всё съест аллокация) и **монотонным**. Критерий выбора k (без доп. модели-аллокатора):

1. считаем softmax роутера $p_1\ge p_2\ge.$
2. берем минимальный k, где $\sum_{i=1}^k p_i \ge \tau$ (например 0.9–0.97),
3. Ставим ограничения: $⁡1 \le k \le K_{\max}$​, плюс сглаживание по времени/слою.
4. Довольно похоже на Ada-K routing (динамическое число активных экспертов) и идеи smarter routing (Ban&Pick указывает, что фиксированный k вводит избыточность) .
